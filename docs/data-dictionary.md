# Data dictionary (implemented Firestore baseline)

This document describes the fields currently read or written by the Flutter models and repositories. It is not a substitute for Firestore security rules or schema validation.

## users/{uid}

- `displayName`, `email`, `role` (`admin` or `it_manager`), `isActive`
- `createdAt`, `updatedAt` (server timestamps where written)

The UID is the Firebase Authentication UID. The client does not create Authentication accounts or passwords.

## offices/{officeId}

- `name`, `building`, `directorate`, `department`, `room`
- `manager`, `phone`, `notes`, `isActive`

## assets/{assetId}

- `category`, `brand`, `model`, `serialNumber`, `status`
- Optional computer attributes: `cpu`, `ram`, `storage`
- Optional office fields: `officeId`, `officeName`
- Optional lifecycle fields written by workflows: `receivedAt`, `transferredAt`, `retiredAt`, `retirementReason`

Categories: `desktop`, `laptop`, `monitor`, `printer`, `scanner`, `network`, `storage`, `ups`, `accessory`, `other`.

Statuses: `available`, `assigned`, `maintenance`, `damaged`, `retired`, `returned`.

## asset_serials/{encodedNormalizedSerial}

Transactional uniqueness reservation index:
- `assetId`, `serialNumber`, `createdAt` or `updatedAt`

The document ID is a Base64URL encoding of the trimmed, uppercased serial number (without padding). Legacy inventory requires a controlled backfill before a large rollout.

## custody_cards/{custodyId}

- `assetId`, `assetLabel`, `employeeName`, `officeName`
- `assignedAt`, `status`, `notes`
- Workflow fields may include `returnedAt` and transfer history references.

## maintenance_records/{maintenanceId}

- `assetId`, `assetLabel`, `title`, `description`, `priority`, `status`
- `reportedAt`, `technician`, `cost`, `resolution`, `previousAssetStatus`
- Completion writes `completedAt`.

## purchase_records/{purchaseId}

- `assetId`, `assetLabel`, `supplier`, `invoiceNumber`
- `purchaseDate`, optional `warrantyUntil`, `totalCost`, `notes`, `createdAt`

## asset_movements/{movementId}

Append-style event records written by asset, custody, maintenance, retirement, and purchase workflows. Depending on event type, fields include:
- `assetId`, `assetLabel`, `movementType`, `occurredAt`, `notes`
- Office transitions: `fromOfficeId`, `fromOfficeName`, `toOfficeId`, `toOfficeName`
- Custody transitions: `custodyId`, `fromEmployee`, `toEmployee`
- Related workflow references: `maintenanceId`, `purchaseId`, optional `cost`

## Security and schema notes

- Firestore document IDs are the stable record identifiers; some models also serialize an `id` field for display compatibility.
- Client deletes are denied for business records. Audit/movement writes are intended to be generated by trusted transaction workflows and protected by the rules.
- Treat field names and timestamp representations as implementation contracts; do not bulk-import data until the Firebase Emulator rules tests and migration/backfill plan are complete.
- The current authorization model is global (`admin` and `it_manager`), not office-scoped.
